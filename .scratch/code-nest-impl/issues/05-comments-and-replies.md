# 05: 评论与回复

**What to build:** 读者可以对已发布的文章发表评论，也可以在某条评论下发表回复，并可指定回复同一评论下的某个人。评论列表和回复列表都是游标分页，每条评论带回复数。评论者可以删除自己的评论或回复；评论被删除后，如果下面还有回复，这条评论显示为"该评论已删除"，回复继续保留。文章的评论数和评论的回复数随增删变化。

## Comments

- **接口细节**：
  - 发表评论、回复返回新记录的 `id`；评论和回复内容都是 1 至 1000 个字符，空白内容返回 400。
  - 评论列表按时间倒序，回复列表按时间正序；两者都用 ID 作游标，`size` 默认 20、范围 1–50，超出返回 400。
  - 草稿、已删除或不存在的文章，评论列表同样返回 404。回复列表对回复 ID 或不存在的评论返回 404（20005）。
  - 新增错误码：20005 评论不存在（404），20006 被回复人不在该评论的讨论中（400）。
  - 删除别人的评论返回通用的 403（90403）；重复删除返回 404。
- **被回复人**：
  - 回复评论时不填 `replyToUserId`，表示回复评论本身，`replyTo` 为 null，不显示"回复 @某人"。
  - 对某条回复再回复时不填，默认 @ 该回复的作者。
  - 通知票据此确定接收者：`replyToUserId` 为空时通知评论作者。
- **已删除的评论**：
  - 列表里 `deleted` 为 true，`content` 为"该评论已删除"，`author` 为 null，回复数照常返回。
  - 不能直接回复已删除的评论（404），它下面的回复仍可以回复；已删除评论的作者也不能再被 @。
  - 回复列表仍可查看已删除评论下保留的回复。
- **自定义 SQL**：`CommentMapper` 有两条 `@Select`，不用链式 Lambda 构造器。原因是 `@TableLogic` 会给构造器查询自动加上 `deleted = 0`，查不到"已删除但仍有回复"的评论。评论列表用 `EXISTS` 子查询判断是否还有回复，只查同一张表，不跨模块联表。
- **`ArticleApi.getCommentBriefs`**：返回评论和回复的摘要（含完整内容，由调用方截断），已删除的不返回，不检查文章状态。
- **并发**：
  - 删除用逻辑删除的返回值判断是否真的删到，并发重复删除只减一次计数。
  - 评论列表与回复数分两次读取，最后一条回复恰好在两次读取之间被删除时，可能短暂出现回复数为 0 的"该评论已删除"。这一点可以接受。
