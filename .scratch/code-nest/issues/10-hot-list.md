# 热榜

Type: grilling
Status: resolved
Blocked by: 06

## Question

（背景：点赞、收藏、评论、浏览量由 [计数系统](06-counter-system.md) 提供。读取时通过 `CounterApi.get` 批量获取；各模块上报计数变更时调用 `CounterApi.increment`。浏览量是近似计数。）

热度公式是什么（点赞/收藏/评论/浏览的权重、时间衰减方式，如 Hacker News 公式）？榜单用 Redis ZSet 实时更新还是定时任务批量计算？榜单周期（日榜/周榜/总榜）与候选集范围？

## Answer

热榜归 article 模块。它读取计数要调用 `CounterApi`，这条依赖（article → counter）原本就存在，不会引入新的模块依赖。

1. **热度公式（仿 Hacker News）**：`hot = (3·点赞 + 5·收藏 + 4·评论 + 0.1·浏览) / (发布小时数 + 2)^1.5`
   - 各项权重和重力系数都做成配置项。
   - 浏览量本身是近似计数，所以权重给得最低。
   - 时间衰减写在分母里，热度会随时间持续下降，因此需要定时重算。
   - 不采用 Reddit 式的增量更新：那样 counter 模块就得发出计数变更事件，多一条事件链路，而热榜允许几分钟的延迟，没有必要。
2. **只有一个榜单**：候选集是最近 7 天内发布、且处于已发布状态的文章，旧文章靠时间衰减自然下沉。
3. **计算**：
   - 定时任务每 5 分钟执行一次。
   - 多实例部署时用 `SET hot:lock NX EX 240` 保证同一时刻只有一个实例在计算。
   - 计算步骤：
     1. 调用 `ArticleApi` 取出最近 7 天发布的文章 ID 与发布时间（本票新增的接口要求）。
     2. 以每批 500 个调用 `CounterApi.get` 取计数。
     3. 算出热度，取前 100 名。
     4. 写入 `hot:articles:tmp`，再用 `RENAME` 原子替换 `hot:articles`，读取方永远看不到只写了一半的榜单。
4. **读取**：
   - `GET /hot-articles?page=` 用 `ZREVRANGE` 分页，每页 20 条，最多 5 页。
   - 批量补全文章摘要（走缓存）和计数。
   - 已删除的文章在读取时过滤掉，下一轮重算时自然不会进入候选集，因此不需要为热榜订阅删除事件。
5. **不做压测对比**：热榜是配角，而且结果本来就预先算好放在 Redis 里。
