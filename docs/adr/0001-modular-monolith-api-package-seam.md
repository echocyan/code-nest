# 模块化单体：跨模块只能调用对方的 `api` 包

码巢是按业务划分的 Maven 多模块单体（`code-nest-modules/*`）。一个业务模块只能使用另一个模块 `api` 包里的门面接口和 DTO；Service、Mapper、Entity 都是模块内部实现，由 ArchUnit 测试强制执行。模块依赖必须单向无环，需要反向通知时发事件：进程内走 Spring `ApplicationEvent`，需要可靠投递的走 MQ。这样既保留单体的开发和部署成本，又让每个模块的接口保持很小，模块内部可以随意重构；将来要拆成服务，也已经有现成的切分线。

## Considered Options

- **直接依赖对方的 Service 或 Mapper**：写起来最省事，但模块边界名存实亡，很快会退化成按层分包的大泥球。
- **每个业务模块再拆一个 `-api` 子模块**：由 Maven 在编译期保证边界，但模块数量翻倍，依赖声明也更繁琐。本项目用一个 ArchUnit 测试就能达到同样的约束。
- **微服务**：会引入注册中心、远程调用、分布式事务等大量与主打技术亮点无关的基础设施，已列为范围外。

## Consequences

- 在 `api` 包里新增东西就是在扩大模块接口，需要慎重。能用 ID 引用的就不要暴露实体。
- 一个模块要读另一个模块的数据时，只能通过对方的门面接口，不能跨模块联表查询；需要时各自冗余必要字段，或在服务层组装。
- 模块对外发布的领域事件类（MQ 消息体）放在 `api/event/` 下，属于模块接口的一部分。改动事件字段等于修改模块接口，需要兼顾所有消费者。
